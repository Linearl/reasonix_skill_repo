# 跨会话上下文恢复技能

## 何时使用

- 新会话开始时，需要继续前序会话的工作
- 用户说"跨会话继续"、"恢复上下文"、"接着做"
- 需要理解前序工作的进展和状态
- 多会话协作时的上下文衔接

---

## 核心问题

每次新会话开始时，AI 需要重新理解：
1. **当前在做什么** - 前序工作的目标和进展
2. **做到哪了** - 已完成、进行中、待处理的任务
3. **有什么约束** - 用户偏好、项目约定、技术限制
4. **下一步该做什么** - 基于前序工作的推荐行动

如果没有系统化的恢复机制，每次都会：
- 重复阅读大量文档
- 重复询问用户相同的问题
- 可能遗漏关键上下文导致偏差

---

## 恢复流程

### Phase 1: 快速状态扫描（< 30秒）

```bash
# 1. 检查 memory 文件（跨会话持久化）
ls -la ~/.Codex/projects/*/memory/MEMORY.md

# 2. 检查当前 git 状态
git status --short

# 3. 检查最近提交（理解前序工作方向）
git log --oneline -10

# 4. 检查任务包状态（如有）
find 02-dev/dev_*/docs/1.task/B.todo -name "*.md" 2>/dev/null | head -5
```

### Phase 2: 上下文恢复（< 2分钟）

```bash
# 1. 读取 memory 文件中的关键记忆
cat ~/.Codex/projects/*/memory/MEMORY.md

# 2. 读取前序会话的工作记录（如有）
ls -lt temp/C--Users-yinji-OneDrive-workspace---------/*.jsonl | head -3

# 3. 读取任务包 README（理解当前任务）
cat 02-dev/dev_*/docs/1.task/B.todo/*/README.md 2>/dev/null | head -100
```

### Phase 3: 状态确认（与用户）

向用户确认：
1. "我理解你正在做 [X]，已完成 [Y]，下一步是 [Z]，对吗？"
2. "有什么新的约束或变化需要我知道吗？"
3. "我推荐的下一步是 [A]，你觉得呢？"

## 与现有系统集成

### 与 Memory 系统集成

- **读取**: 从 `~/.Codex/projects/*/memory/MEMORY.md` 读取持久化记忆
- **写入**: 每次会话结束时，将关键上下文写入 memory
- **更新**: 当前序记忆过时时，主动更新或删除

### 与 Git 集成

- **git log**: 通过提交历史理解工作方向
- **git status**: 了解当前工作区状态
- **git diff**: 理解未提交的变更

### 与任务系统集成

- **B.todo**: 读取待办任务了解当前重点
- **B.2.done**: 读取已完成任务了解历史
- **README.md**: 读取任务包 README 了解整体目标

## 最佳实践

### 做

1. **先扫后读** - 先快速扫描状态，再深入读取关键文件
2. **确认理解** - 与用户确认理解是否正确
3. **推荐行动** - 基于上下文给出推荐的下一步
4. **记录关键信息** - 会话结束时更新 memory

### 不做

1. **不要重复阅读所有文档** - 只读关键文件
2. **不要假设理解正确** - 必须与用户确认
3. **不要遗漏约束** - 特别是用户偏好和项目约定
4. **不要跳过确认** - 直接开始工作可能导致偏差

## 示例

### 用户说"跨会话继续"

AI 执行：
1. 快速扫描 git status、最近提交、任务包状态
2. 读取 memory 文件中的关键记忆
3. 输出恢复报告，确认理解
4. 等待用户确认后继续工作

### 用户说"恢复上下文"

AI 执行：
1. 同上流程
2. 额外读取前序会话的工作记录（如有）
3. 输出更详细的恢复报告

## 触发条件

### 中文关键词

- 跨会话继续
- 恢复上下文
- 前序工作
- 会话衔接
- 上下文恢复

**注意**：不要使用"继续"作为触发词，因为太容易误触发。用户说"继续"可能只是想继续当前会话的工作，而不是恢复跨会话上下文。

### English keywords

- resume session from previous
- restore context
- previous work
- session context
- context restore

**Note**: Do not use "continue" as a trigger word, as it's too easy to误触发. The user saying "continue" may just want to continue the current session's work, not restore cross-session context.
