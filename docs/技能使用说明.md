# 技能使用说明

每个技能的详细使用说明。场景、触发方式、关键步骤与注意事项均以各自 `SKILL.md` 为准，本文档是快速索引。

## 1. patent-search（专利检索）

- **场景**：专利检索与可专利性分析——innojoy/Google Patents 自动化检索、检索式设计、对比文件分级、新颖性/创造性评估、交底书撰写。
- **前置**：⚠️ 公司 innojoy 账号；公司网络环境。
- **触发**：「检索 XX 技术的现有专利，评估新颖性」「帮我写交底书」。
- **注意**：凭据按 SKILL.md 的账号配置方式注入，**严禁写入任何仓库/提交**。

## 2. book-to-skill（书籍提取成技能）

- **场景**：把 PDF/EPUB/DOCX/HTML/Markdown/纯文本/RTF/MOBI/AZW 等文档提炼为结构化 agent 技能（框架、心智模型、原则、技术、反模式）。
- **触发**：「把这本书提炼成技能」「读完这份文档并沉淀成 playbook」。
- **流程**：`extract.py` 提取全文 → 生成 SKILL.md + chapters/ + glossary/patterns/cheatsheet + source/full-text.md。
- **注意**：MOBI/AZW 需 Calibre 转换；Python 3.9+。

## 3. web-scraping（网页抓取）

- **场景**：任意网页抓取完整内容整理为 Markdown（文字 + 图片本地化）。
- **能力**：探测 SSR/API 数据源、处理限流（B 站 -509 等）、CDP 复用 Chrome 登录态（`--remote-debugging-port` + `connect_over_cdp`）、wbi 签名（参考 MediaCrawler 的 `BilibiliSign`）。
- **触发**：「抓取这个 B 站文集的全部文章，图片本地保存」。
- **合规**：遵守目标站点服务条款与所在地区法规；登录态复用仅限自有账号。
- **参考项目**：[MediaCrawler](https://github.com/NanmiCoder/MediaCrawler)（自行拉取，本仓库不附带）。

## 4. image-ocr-to-docs（本地 OCR）

- **场景**：图片目录批量 OCR 成可检索文字（游戏截图/攻略图/聊天记录/票据），输出同名 .md 或汇总清单。
- **能力**：PaddleOCR + 放大预处理（小字截图）、双引擎交叉验证、grep 可检索。
- **触发**：「把这个图片文件夹全部 OCR 成 markdown」。
- **注意**：纯本地推理（数据不出内网）；首次需 `pip install paddleocr paddlepaddle Pillow`。

## 5. migrate-reasonix-project（项目迁移保留历史）

- **场景**：移动/重命名 Reasonix（及 Claude Code）项目目录时保留全部对话历史。
- **触发**：「把项目文件夹从 A 移到 B，保留对话历史」。
- **覆盖**：会话文件（`%APPDATA%\reasonix\projects\`）、meta 路径改写、检查点与子代理元数据。
- **注意**：迁移前先退出该项目的所有会话；迁移后验证历史可加载。

## 6-9. Obsidian 系列（markdown / bases / cli / vault-organize）

组合流水线：**抓取（3）→ obsidian-markdown 规范化 → obsidian-vault-organize 整理**；OneNote 旧笔记经（10）导入后同流水线。

| 技能 | 用途 | 触发 |
|------|------|------|
| obsidian-markdown | wikilink/embeds/callouts/properties/frontmatter 语法规范 | 「按 Obsidian 语法改写这篇笔记」 |
| obsidian-bases | Bases（.base）视图：表格/卡片/过滤器/公式/汇总 | 「给这些笔记建一个 Bases 视图」 |
| obsidian-cli | vault CLI：创建/搜索/管理笔记、任务、插件开发 | 「用 CLI 在这个 vault 里搜索 XX」 |
| obsidian-vault-organize | 批量整理：移动/重命名/归档后全 vault 重写引用 + 断链归零 | 「整理这个 vault，检查断链」 |

## 10. onenote-to-obsidian（OneNote 导入）

- **场景**：OneNote .one 文件（本地导出或缓存副本）→ Markdown → Obsidian；**不依赖同步状态**，适合同步失败/分区被删/importer 漏导的本地恢复。
- **能力**：OneNote COM API（PowerShell 调用）逐页导出 → XML 解析（span 剥离/checkbox/缩进）→ 按季度/分区组织导入。
- **脚本**：`scripts/onenote_export.ps1` + `scripts/parse_onenote_xml.py`。
- **注意**：仅 Windows；需本机安装 OneNote 桌面版；导出会跳过同步失败的页面（报错页 = 缺失页，修复同步后重导）。

## 11. reasonix-remote-linux-setup（Linux 远程部署）

- **场景**：在 Linux 远程主机（含绿联 NAS 等容器化/魔改系统）上安装/配置 reasonix serve，并打通 Windows 桌面版远程连接。
- **覆盖**：serve 监听/认证、SSH/SFTP 虚拟视图坑（标准 sshd 2222 方案）、桌面版远程窗口、代理接入。
- **触发**：「在 NAS 上部署 reasonix 并打通桌面版远程连接」。
- **注意**：含大量实战踩坑记录，部署前通读 SKILL.md 的「已知坑」清单。

## 12. reasonix-sync-deploy（多机同步接入）

- **场景**：新电脑接入 reasonix-sync 多机同步体系（OneDrive 同步用户级技能 + 全局记忆）。
- **流程**：环境探测 → OneDrive 始终保留提示 → 创建定时任务（StartWhenAvailable 错过补跑）→ 首次推送并验证。
- **前置**：已有一套 reasonix-sync 体系（同步脚本 + 审查技能 + 主力机）。
- **触发**：「把这台新电脑接入同步体系」。
